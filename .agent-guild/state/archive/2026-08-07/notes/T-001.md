# T-001 notes

## Diagnosis confirmed

`tests/apps.bats` setup() did `export PATH="$STUBS:$PATH"`. The case at (now)
line ~262, "names the missing tool rather than failing somewhere inside a
pipeline", writes a stub `fzf` and then `rm`s it to simulate a machine with no
`fzf`. Since the real `$PATH` was still appended, `command -v fzf` inside
`dot_local/bin/executable_dotfiles-apps` fell through to
`/opt/homebrew/bin/fzf`, the dependency guard passed, `main()` defaulted to
move mode, and the run blocked on `fzf`'s interactive picker forever.

## Fix

Two changes, both inside `setup()`:

1. Added `REAL_JQ="$(command -v jq)"` at file scope (before `setup()` ever
   runs, mirroring the existing `REAL_CHEZMOI="$(command -v chezmoi)"` pattern
   already used in `tests/doctor.bats`), so jq's real absolute path is
   captured while `$PATH` is still the inherited one.
2. Replaced the trailing `export PATH="$STUBS:$PATH"` with:
   - `ln -sf "$REAL_JQ" "$STUBS/jq"` — jq is never stubbed or removed by any
     case in this file, but on this machine it lives in the same Homebrew bin
     directory (`/opt/homebrew/bin`) as the real `fzf`/`chezmoi`/`brew`. Once
     that directory is dropped from `PATH` (next line), jq would vanish with
     it unless carried over explicitly.
   - `export PATH="$STUBS:/usr/bin:/bin"` — `$STUBS` is now authoritative for
     the three tools it stubs (`fzf`, `chezmoi`, `brew`): removing a stub file
     genuinely makes that command unresolvable, since nothing later on `PATH`
     can supply it. `/usr/bin` and `/bin` still carry the real `bash`, `git`,
     and every coreutil the script and test file use (`awk`, `sed`, `mktemp`,
     `mv`, `chmod`, `stat`, `grep`, `wc`, `tr`, `dirname`, `cut`, `tail`,
     `cat`, `rm`, `mkdir`, `paste`), none of which this suite ever stubs.

I confirmed by grep that no other case in `apps.bats` ever removes the
`chezmoi` or `brew` stub — only `fzf`, at the one case the task names — so
those two never needed the same real-binary fallback treatment.

## Judgment call

The obvious alternative — resolve directories dynamically and exclude
whichever ones held `fzf`/`chezmoi`/`brew`'s real binaries — is more portable
across machines but heavier for a fix scoped to "this machine." I went with
the narrower, concrete `/usr/bin:/bin` allowlist since it mirrors an existing
convention in this same test suite: `tests/font.bats:316` and
`tests/licensed-fonts.bats:44` already use a hand-picked
`PATH="$STUBS:/usr/bin:/bin"` (or a subset) per-test to simulate a missing
tool, and `tests/doctor.bats:18` already resolves a real tool's path before
`setup()` overrides `PATH`. This fix applies both of those established
patterns at the `setup()` level instead of inventing a new mechanism.
