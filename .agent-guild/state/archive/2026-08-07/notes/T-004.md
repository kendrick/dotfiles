# T-004 notes

## Approach

Added one case to `tests/doctor.bats`, titled exactly `doctor: a tracked but
uninstalled formula is reported`, plus a small helper (`homebrew_section()`)
mirroring the existing `deps_section()` pattern but scoped to the `== Homebrew ==`
block instead of `== Config dependencies ==`.

The case writes a `packages.json` fixture with one `brew`-type package
(`fixture-missing-formula`) in the `fonts` bundle — the bundle `setup()` already
enables by default via `write_bundles fonts`. Since `brew` is stubbed as `:` in
`setup()`, `brew list --formula` returns nothing, so the fixture formula never
matches `installed_brew` and the doctor falls into the
"in a bundle you've enabled but not installed" branch at
`dot_local/bin/executable_dotfiles-doctor:58-68`. The assertion checks both the
section header text and the formula name appear in output.

Placed the helper and the test right after `deps_section()`/before
`write_registry()`'s consumers, since it exercises a different section of the
script than the other 10 cases (all of which cover Config dependencies) — grouping
it with the helpers keeps the fixture-shape comments below it intact and
undisturbed.

## Judgment calls

- Used a `brew`-type fixture entry (not `cask`) so the Config dependencies section,
  which filters on `type == "cask"`, ignores it — avoids any interaction with the
  other 10 cases' registry/cask assertions.
- Didn't add a font registry fixture for this case; the Config dependencies
  section just prints "font registry not found ... skipping" when absent, which
  doesn't interfere with the Homebrew section under test.
- New test placed first in file order (before the existing 10), since it targets
  a different script section — a purely organizational choice, not required by
  the spec.
