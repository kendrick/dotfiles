## Spec excerpt

`bats tests/` does not terminate on this machine. Every other task in this job is
verified by running that suite, so this blocks all of them and goes first.

**The defect.** `tests/apps.bats:58` prepends the stub directory to `$PATH`
without scrubbing the rest of it:

```bash
PATH="$STUBS:$PATH"
```

The case at `tests/apps.bats:256` — "names the missing tool rather than failing
somewhere inside a pipeline" — writes a stub `fzf` and then removes it, intending
to simulate a machine without `fzf`:

```bash
printf '#!/usr/bin/env bash\nexit 127\n' >"$STUBS/fzf"
rm "$STUBS/fzf"
```

Because the real `PATH` is still appended, `command -v fzf` finds
`/opt/homebrew/bin/fzf`. The guard at `dot_local/bin/executable_dotfiles-apps:35`
passes, `main()` defaults `mode="move"` at `:258`, and the run blocks forever on
`cmd_move`'s picker at `:144` waiting for input that never comes.

This is latent on a machine without `fzf` installed and fires on one with it.
`fzf` was installed here on 2026-08-06 — the same install that produced the
incident behind this issue.

**What to do.** Make the stub `PATH` authoritative for the tools the suite
stubs, so removing a stub actually makes that tool absent. The obvious shape is
to stop appending the inherited `PATH`, but the suite still needs the real
`bash`, `git`, `jq`, and coreutils, so a bare `PATH="$STUBS"` will break other
cases. Work out the narrowest change that makes case `:256` see no `fzf` while
the other 17 cases in the file keep passing.

**Constraints.**

- Do not modify `dot_local/bin/executable_dotfiles-apps`. The bug is in the test
  harness, not the tool. `dot_local/` is outside this job's scope allowlist and
  editing it fails clause D-1.
- Do not delete or skip the offending case. `tests/apps.bats` has 18 `@test`
  blocks at baseline and must still have at least 18.
- The full suite must terminate. Verify with `timeout 300 bats tests/` and
  confirm it exits 0, not 124.
- Everything else in `tests/` is other tasks' territory. Touch only
  `tests/apps.bats`.

**Why this is in the job at all.** It is unrelated to issue #17 and was folded in
by the user's decision, because the spec's own `Verify with: bats tests/` and
acceptance criterion 8 are unsatisfiable until the suite runs.
