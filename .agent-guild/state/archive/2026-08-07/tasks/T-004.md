## Spec excerpt

Acceptance criterion 5: after an apply where a package failed to install,
`dotfiles-doctor` should report that package under "in a bundle you've enabled
but not installed". The spec asks for this to be **confirmed, not assumed** —
"Worth confirming that's true rather than assuming it." It is what makes a failed
install outlive the scrollback, so the whole reporting design leans on it.

**Add one case to `tests/doctor.bats`**, titled exactly:

```text
doctor: a tracked but uninstalled formula is reported
```

It must exercise the branch that `dot_local/bin/executable_dotfiles-doctor:58-68`
emits, headed:

```text
-- in a bundle you've enabled but not installed (next apply installs these):
```

**This is easier than it looks.** The existing harness already stubs `brew` as
`:` at `tests/doctor.bats:52`, so nothing reads as installed. Reaching the branch
needs only a `packages.json` fixture entry naming a formula the stubbed
`brew list` does not return. Follow the fixture patterns the file's other 10
cases already use.

**Do not modify the doctor.** `dot_local/` is outside this job's scope allowlist
and editing it fails clause D-1. The doctor's behaviour is correct; this task
proves it.

**The trap this case must avoid.** A case that stubs `brew list` to *return* the
tracked formula never reaches the missing branch. It passes at HEAD and would
pass just as well against a doctor with the branch deleted — proving nothing. The
checker detects exactly this by deleting lines 58-68 from a copy of the doctor
and requiring your case to fail. If it still passes, the case is not exercising
what it claims.

You can run that check yourself before handing the task back:

```bash
git worktree add /tmp/agc-mut HEAD
cp tests/doctor.bats /tmp/agc-mut/tests/
sed -i '' '58,68d' /tmp/agc-mut/dot_local/bin/executable_dotfiles-doctor
cd /tmp/agc-mut && bats --formatter tap tests/doctor.bats
git worktree remove /tmp/agc-mut --force
```

Your case must report `not ok` there and `ok` in the real tree.

**This task does not wait on the apps.bats hang fix.** Both of its checks run
`tests/doctor.bats` alone, never the full suite, so the hang is irrelevant here.
The dependency was removed after decomposition for that reason.

**Keep the existing 10 cases passing.** `tests/doctor.bats` has 10 `@test` blocks
at baseline and must still have at least 10, none skipped.
