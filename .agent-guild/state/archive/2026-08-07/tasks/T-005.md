## Spec excerpt

Two passages in `_working-memory/conventions.md` describe the convention this job
just removed. Left stale, they are what the next agent reads before reintroducing
the bug — the spec calls this out directly at `spec.md:43`, citing conventions.md
as the reason the guards exist.

**1. The Error Handling bullet, `_working-memory/conventions.md:46`.**

It currently reads, in part:

> external-tool installers (`brew bundle`, `code --install-extension`,
> `open raycast://`) guard each call with `|| true` and skip cleanly if the CLI is
> absent. _(run_onchange_install-vscode-extensions.sh.tmpl, run_once_after_configure-macos.sh)_

It cites `run_onchange_install-vscode-extensions.sh.tmpl` as the exemplar — the
file this job converts. Rewrite it to state the rule this job establishes: an
absent tool is skipped with a message, and a present tool's failure is named. The
`run_once_after_configure-macos.sh` half of the citation stays true and should
survive; that script's guards are deliberate and out of scope.

**2. The bats bullet, `_working-memory/conventions.md:40`.**

It currently reads:

> Don't reach in for helper functions and don't assert on log wording: what
> matters is what the run left on disk and whether it refused when it should have.

`tests/install-failures.bats` asserts on log wording throughout — that is the
entire point of clause B-2, which requires the failing item's name to appear in
the output. Amend the bullet to carve out output assertions where the output _is_
the contract under test, without licensing wording assertions generally. The rest
of the bullet — don't reach in for helper functions — stays true and should
survive.

**3. A dated entry in `_working-memory/decisionLog.md`.**

Record the decision and the incident behind it: `fzf` was added to the `core`
bundle on 2026-08-06, `chezmoi apply` ran, `install-packages.sh` was recorded in
chezmoi's `scriptState` as done at `18:28:36Z`, and `fzf` was never installed.
Nothing errored, nothing retried, and the failure only surfaced when a tool
depending on `fzf` refused to start. Follow the file's existing entry format
(**Context** / **Decision** / **Alternatives considered**), newest at the top.

The alternatives the issue already rejected, worth recording so they are not
re-proposed: aborting the apply on first failure, retrying failed installs
automatically, and withholding `run_onchange` state so chezmoi re-runs the script.
