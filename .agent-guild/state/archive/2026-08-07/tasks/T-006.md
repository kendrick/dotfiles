## Spec excerpt

Every other task's artifacts are sitting uncommitted. This task lands them.

**Run the scope check first, before committing.**
`.agent-guild/scripts/check-diff-scope.py` reads only the working tree, so once
you commit it reports OK regardless of what the commits touched. Run it while the
work is still uncommitted:

```bash
python3 .agent-guild/scripts/check-diff-scope.py \
  --ignore dot_claude/encrypted_private_settings.json.age \
  run_onchange_install-packages.sh.tmpl \
  run_onchange_install-vscode-extensions.sh.tmpl \
  run_onchange_configure-raycast.sh.tmpl \
  run_onchange_after_install-claude-plugins.sh.tmpl \
  tests/ _working-memory/conventions.md _working-memory/decisionLog.md
```

It must exit 0. If it names an out-of-scope path, stop and report rather than
committing — something earlier in the job went outside its lane.

`dot_claude/encrypted_private_settings.json.age` was already modified when the
job started. It is the user's, not this job's. Leave it uncommitted and untouched.

**Commit shape.** Commits that each stand on their own. The natural seams follow
the tasks: the apps.bats harness fix is unrelated to issue #17 and should be its
own commit rather than smuggled in with the conversion.

**Message standard**, from `~/.claude/CLAUDE.md`:

- Cover the **why** as much as the what. A message that only restates the diff
  fails clause D-3.
- No `Co-Authored-By` or any other attribution trailer. None.
- Never hard-wrap the body. Let the pager wrap at display time.
- Voice: a helpful technical writer in a hurry. Common abbreviations are fine.
- Run the messages through the `humanizer` skill before committing. Standing
  requirement, not a preference.

The why worth capturing: a failed install was indistinguishable from a clean one,
and because `run_onchange_` scripts record themselves done by content hash,
nothing ever retried. `fzf` was added to the `core` bundle on 2026-08-06, the
apply recorded success, and `fzf` was never installed.

**Do not push.** Not `git push`, not a force-push, not "just the one branch". The
user pushes, always. A pushed commit fails clause D-3, and the checker detects it
with `git branch -r --contains` — which catches it even though the older
`origin/main..HEAD` form could not.

**Leave the tree clean** of this job's paths when you finish.

**Do not** run `chezmoi apply` or `chezmoi update`, edit `.chezmoidata.toml`, or
install anything. Clause D-4 checks the chezmoi state database's mtime, so an
apply is detectable even if you revert its effects.

**One environmental note.** The `com.k-arnett.dotfiles-auto-sync` LaunchAgent was
unloaded for this job because it runs `git add -A` and commits on a timer. If you
see a commit whose message begins `[auto-sync from`, it is not yours — stop and
report it rather than building on it.
