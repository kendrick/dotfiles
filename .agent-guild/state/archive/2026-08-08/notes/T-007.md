# T-007 self-report

## What I built

`tests/mutation-check.sh`, a bash script (no `set -e`; avoided on purpose since
every fallible command here is already behind an explicit `if`/`while`, and
bash 3.2's errexit bug only bites a *bare* `[[ ]]`/`(( ))` statement — never
present here — not one guarded by `if`).

## Enumeration

Two passes, run per target file (the six named in the task; `install-failures.bats`
and `lint.bats` are never in the scan list, and the script prints why on every
run):

1. `assert_contains`/`assert_not_contains` calls — a first-non-whitespace-token
   grep, walking backward from each hit to the nearest preceding `@test "..." {`
   line to capture the enclosing case name. The backward walk stops (and the site
   is treated as having no enclosing test) if it hits an unindented `}` first —
   verified against all six files that every `@test`/function body closes on an
   unindented `}` while nested `{ ...; }` groups and `${...}` expansions never do.
2. `doctor.bats`'s one `case "$output" in *undeclared* | *casks*) ;; ...` block,
   found by grepping for a line containing both glob needles `*undeclared*` and
   `*casks*` together — not just the two bare words, which I initially got wrong
   (see Bugs below) — then the same backward walk for its enclosing test name.

A third pass looks for `true`/`false`/`:` as a line's entire content inside a
`@test` body: this is the "unrecognised form" case (V-2 part 3's `true`
substitution). If found, the script prints every `file:line` and exits 1
*before* mutating anything, without running any mutation testing that run.
None of the three target patterns overlaps with `packages.bats`'s
`[ -n "$cask" ] || continue` guards (single-bracket, not matched by any of the
three), so the guard is excluded by construction, not by a special case — the
script just says so in its startup banner per the task's ask.

All three passes run over a `strip_heredocs` helper that tracks heredoc state
(including the `<<-DELIM` variant with a tab-stripped terminator, which
`font.bats`'s stub scripts use) so heredoc payload — a JSON fixture's own
`true`, a stub script's own `esac` — can never be misread as code.

Verified empirically: on the current tree, the "unrecognised" and
placeholder-detection scans report nothing extra across all six files — no
false positives from `write_registry`/`write_config`/`shift` (all live inside
`setup()`/helper functions, never inside a `@test` body) or from multi-line
single-quoted jq filters (`to_entries` etc. never collapse to a bare `true`/
`false`/`:` shape).

## Pass/fail judgment: TAP by name, never exit status

For each recognised site: back the file up (`mktemp` + `cp`), mutate that one
line (helper-name swap via `awk sub()`, or sentinel-replace both needles for
the case block via `awk gsub()`), run `bats --formatter tap <file>`, and scan
the TAP output for a line matching `^not ok [0-9]+ (.*)$` whose captured
remainder equals the site's enclosing test name **verbatim** (string compare,
not regex, so parens/quotes in a test's own description can't be misread as
metacharacters). File-level exit status is never consulted. Restore from
backup immediately after, via a trap that also fires on INT/TERM.

## Two bugs found and fixed while testing (before reporting done)

1. **Case-block needle search matched the wrong line.** My first version
   grepped for any line containing both the bare words "undeclared" and
   "casks" — which also matches the `@test` header itself
   (`@test "a half with no casks key at all is reported as undeclared" {`),
   since the test's own name contains both words in prose. Caught immediately:
   scoping to `doctor.bats` alone reported line 233 (the header) as
   "unrecognised." Fixed by requiring the glob-shaped needles `*undeclared*`
   and `*casks*` together, which only the real `case` arm at line 251 has.
2. **`<<-'STUB'` heredocs broke `strip_heredocs` for the rest of the file.**
   `font.bats` uses the dash variant (tab-indented terminator) for its stub
   scripts; my terminator check compared the raw line against the bare
   delimiter string, so it never matched `"\t\tSTUB"` and the parser thought
   it was inside a heredoc for the rest of the file — font.bats reported 0
   sites instead of 12. Fixed by tracking whether `-` was seen and, if so,
   stripping leading tabs from the candidate line before comparing.

Both were caught by running each file individually against real `bats` output
before trusting the full pass, not by inspection.

## Judgment calls

- **Unrecognised-form detection is intentionally narrow** (bare `true`/
  `false`/`:` only), not a general "any bareword statement" scanner. A
  broader heuristic would false-positive on the codebase's own bare
  zero-arg calls (`write_registry`, `write_config`, `shift`) and on
  multi-line single-quoted jq filters (`to_entries` etc. as a lone token
  mid-expression) unless scoped correctly — I chose the narrow, verified-safe
  pattern over a general parser, since the task's own example (V-2 part 3)
  is specifically a `true` substitution and getting a general bash statement
  classifier right without false-positiving on this exact corpus is a much
  larger, riskier undertaking than the spec asks for.
- **On finding an unrecognised site, the script aborts before mutating
  anything** rather than running the mutation loop for the rest of that pass
  first. The clause says "reported... and the script exits non-zero" without
  specifying ordering; fail-fast seemed the more defensible reading and
  avoids burning ~6 minutes of bats runs when the enumeration itself is
  already known-bad.
- **No `set -e`.** Every fallible operation is behind an explicit `if`
  already, and this makes the "restore even on interrupt" trap simpler to
  reason about than mixing errexit with explicit exit-code checks would be.
