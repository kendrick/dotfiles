## Spec excerpt

Create `tests/helpers.bash`, the one place this repo's bats assertions are defined, and wire every existing test file to load it.

**Why this exists.** Under bash 3.2 — `/bin/bash` on every stock macOS, and the shell bats runs test bodies under — a failing `[[ ]]` inside a function does not abort that function unless it is the function's literal last statement. Anywhere else its failure is silently discarded. A test whose assertion is false therefore reports `ok` as long as any later command succeeds. `grep`, `case`, `[ ]`, and a function that returns non-zero all propagate correctly; `[[ ]]` and `(( ))` do not. Every other task in this job converts call sites to use what you build here, so a mistake in this file disarms the entire suite at once.

**What to build.**

**First**, `tests/helpers.bash` defining exactly these two functions, which already exist verbatim at `tests/install-failures.bats:73-83` and are known-good — move them, do not redesign them:

```bash
assert_contains() {
	local needle="$1" haystack="${2-$output}"
	grep -qF -- "$needle" <<<"$haystack"
}

assert_not_contains() {
	local needle="$1" haystack="${2-$output}"
	case "$haystack" in
	*"$needle"*) return 1 ;;
	esac
}
```

  The second argument defaults to bats' `$output`, so a call site asserting against `$output` passes one argument and a call site with a computed haystack passes two. Later tasks depend on both forms.

**Second**, add a `load` line to all seven existing test files: `apps.bats`, `doctor.bats`, `font.bats`, `install-failures.bats`, `jsonc.bats`, `licensed-fonts.bats`, `packages.bats`. bats resolves `load 'helpers'` to `helpers.bash` beside the test file. No file uses `load` today, so you are introducing the convention — put it at the top, above any `setup()`.

**Third**, delete the two local definitions from `tests/install-failures.bats:73-83`, leaving that file to use the shared ones. Keep the explanatory comment above them (`:67-72`) — move it to `helpers.bash`, where it now belongs. It is the best existing description of this bug in the repo.

**Constraints.**

- Helper bodies use only `grep`, `case`, `[ ]`, or a plain `return`. A helper containing `[[` or `(( ))` reintroduces the bug at the root and fails B-1 and B-3 both.
- Do not change any existing assertion in any file. This task adds the helpers and the `load` lines only; the 54 call-site conversions belong to T-002 through T-005 and will conflict if you start them here.
- `bats tests/` must still pass when you are done. Adding `load` lines and removing now-shared definitions should be behaviour-neutral; if the suite goes red, that is a real problem with this task, not something for a later task to clean up.

**Verify before reporting done.**

```bash
bats tests/                                    # still 119 passing
/usr/bin/grep -c 'load ' tests/*.bats          # every file has one
/usr/bin/grep -nE '^[[:space:]]*(\[\[|\(\()' tests/helpers.bash   # nothing
```
