## Spec excerpt

Convert all 20 bare `[[ ]]` assertions in `tests/doctor.bats` to shared-helper calls. This is the largest single file in the job.

**Why.** Under bash 3.2 — the shell bats runs test bodies under — a failing `[[ ]]` inside a function is silently discarded unless it is the function's last statement. A false assertion followed by any successful command reports `ok`. `grep` and `case`, which the helpers use, propagate correctly from any position.

**The helpers**, already built by T-001 in `tests/helpers.bash` and loaded by this file:

- `assert_contains "needle"` — asserts `$output` contains the needle
- `assert_contains "needle" "$haystack"` — explicit haystack
- `assert_not_contains "needle"` / `assert_not_contains "needle" "$haystack"`

**The 20 sites, at baseline (`61213fe`) line numbers — every one is now +2 in the working tree**, because T-001 added a `load` line and a blank above them. Find each site by its text, not by jumping to the number. Every one asserts against `$output`, so every one takes the single-argument form. `==` becomes `assert_contains`, `!=` becomes `assert_not_contains`:

**Watch the polarity.** Four of these are `!=` (140, 175, 195, 228) and sit next to near-identical `==` lines. Converting `[[ "$output" != *"none"* ]]` to `assert_contains "none"` inverts the test, leaves the suite green because the output does contain that word, and makes the case assert the opposite of what it was written to prove. That is this task's stated failing example.

**Line 244 is the one that needs judgment.** It is the suite's only disjunction:

```bash
[[ "$output" == *"undeclared"* || "$output" == *"casks"* ]]
```

Neither helper converts it directly. Restructure it into an explicit form whose failure propagates and whose intent stays visible — an `if` testing both substrings that returns 1 when neither matches. **Both substrings must survive.** Narrowing it to whichever arm happens to pass today changes what the assertion checks, which is an explicit non-goal of this job.

**Build this one out of `case` or `grep` directly, not out of `assert_contains` calls.** The constitution permits either and will not fail you on the count, but two downstream artifacts pin numbers that a helper-built version breaks: `tests/mutation-check.sh` enumerates helper call sites and its check pins doctor at exactly 20, so an `if` made of two helper calls makes it count 21. Worse, both of that script's mutation rules would then claim these lines — polarity swap by name, and sentinel-needle by site — leaving it no defined behaviour here. One plain `if` keeps this site unambiguous for every consumer. Something like:

```bash
	case "$output" in
	*undeclared* | *casks*) ;;
	*) return 1 ;;
	esac
```

is enough, and `case` propagates correctly from any position under bash 3.2, which is the property that matters.

**Do not** change what any assertion checks, retitle a case, delete a case, or touch `dot_local/bin/executable_dotfiles-doctor`. If a converted assertion fails, the conversion is wrong — the doctor is not in scope and must not be "fixed" to satisfy a test. `tests/doctor.bats` must still report 11 cases and pass.

**Verify before reporting done.**

```bash
/usr/bin/grep -nE '^[[:space:]]*(\[\[|\(\()' tests/doctor.bats   # nothing
/usr/bin/grep -c '^@test' tests/doctor.bats                      # still 11
bats tests/doctor.bats                                           # passes
```

## Orchestrator ruling: `case` where B-2 names an `if`

T-009's checker flagged, without ruling, that `tests/doctor.bats` implements the disjunction as a `case` with a `*) return 1 ;;` arm, while B-2's text says "an `if` testing both substrings that returns 1 when neither matches."

**The divergence is mine, and the implementation is correct.** B-2 was written before the DEC-audit found that a helper-built `if` would collide with `mutation-check.sh`'s enumeration — doctor would count 21 sites instead of 20, and both mutation rules would claim the same lines. My rework instruction to T-002 said to build it from `case` or `grep` directly. The worker followed the instruction; the constitution clause was never updated to match.

B-2's operative requirements are that both substrings survive, that polarity is preserved, and that the failure propagates from a non-last position. The shipped `case` meets all three, verified: both `*undeclared*` and `*casks*` are present, sentinel-substituting both turns the case red, and `case` propagates under bash 3.2 where `[[ ]]` does not. "An `if`" was illustrative of the shape, not a normative construct requirement — the clause's own check tests the properties, not the keyword.

Recorded rather than quietly accepted, because the checker was right to notice that a clause and its artifact name different constructs, and a future reader comparing the two deserves to know which one governs and why.
