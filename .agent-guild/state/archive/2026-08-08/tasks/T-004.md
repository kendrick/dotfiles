## Spec excerpt

Convert all 11 bare `[[ ]]` assertions in `tests/apps.bats`. Five assert against a computed haystack and four of those carry needles full of literal quotes and brackets, so the quoting is the whole difficulty here.

**Why.** Under bash 3.2 — the shell bats runs test bodies under — a failing `[[ ]]` inside a function is silently discarded unless it is the function's last statement. `grep -qF` and `case`, which the helpers use, propagate correctly from any position.

**The helpers**, built by T-001 in `tests/helpers.bash` and loaded by this file. Both compare literally — `assert_contains` uses `grep -qF -- "$needle"`, so needles are fixed strings, not patterns, and a needle starting with `--` is safe because of that `--` guard:

- `assert_contains "needle"` — asserts against `$output`
- `assert_contains "needle" "$haystack"` — explicit haystack

All line numbers below are baseline (`61213fe`) and are **now +2 in the working tree**, since T-001 added a `load` line above them. Locate each site by its text rather than jumping to the number.

**The six `$output` sites**, all `==`, all becoming the single-argument form:

| line | needle |
| --- | --- |
| 179 | `found 0` |
| 202 | `nothing untracked` |
| 274 | `fzf` |
| 280 | `unknown option` |
| 286 | `--adopt` |
| 287 | `--machine` |

**The five `registry_line` sites.** Each needs the haystack as a second argument, and each needle was written single-quoted precisely because it contains double quotes — keep it that way:

```bash
# :135
assert_contains 'bundles = ["media"]' "$(registry_line 'owner/repo/x')"
# :142
assert_contains '["cloud"]' "$(registry_line spotify)"
# :143
assert_contains '["cloud"]' "$(registry_line 1password)"
# :150
assert_contains 'bundles = ["core", "media"]' "$(registry_line spotify)"
# :190
assert_contains '{ name = "yq", type = "brew", bundles = ["core"] },' "$(registry_line yq)"
```

Line 190's needle includes the trailing comma. It is part of the assertion — the test is pinning the exact rendered TOML line, comma included — so do not tidy it away.

**Leave line 50 alone.** It contains `[[` but is not an assertion:

```bash
grep -oE '\{ name = "[^"]+", *type = "[^"]+", *bundles = \[[^]]*\] \}' "$FIXTURE/.chezmoidata.toml" \
```

That is a bracket expression inside a `grep -oE` pattern. A naive `grep '\[\['` over this file returns 12 hits; only 11 are commands. Touching line 50 breaks `registry_line`, which five of your conversions depend on.

**Do not** change what any assertion checks, delete or retitle a case, or touch `dot_local/bin/executable_dotfiles-apps`. `tests/apps.bats` must still report 18 cases and pass.

One historical note, so you do not rediscover it the hard way: this file once hung forever because a stub `fzf` was removed while the real one stayed on `PATH`, and the picker blocked. That was fixed in the #17 job. If your run hangs rather than fails, you have changed something about how this file stubs `PATH`, which is out of scope for this task.

**Verify before reporting done.**

```bash

/usr/bin/grep -c '^@test' tests/apps.bats                      # still 18
```
