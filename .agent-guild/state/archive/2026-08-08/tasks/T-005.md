## Spec excerpt

Convert the remaining 11 bare `[[ ]]` sites across three small files. Ten are ordinary assertions; the eleventh is not an assertion at all and is the one to read carefully.

**Why.** Under bash 3.2 — the shell bats runs test bodies under — a failing `[[ ]]` inside a function is silently discarded unless it is the function's last statement. `grep -qF` and `case`, which the helpers use, propagate correctly from any position.

**The helpers**, built by T-001 in `tests/helpers.bash` and loaded by all three files: `assert_contains "needle"` and `assert_not_contains "needle"`, both defaulting to `$output`. Every assertion below asserts against `$output`, so all ten take the single-argument form.

All line numbers below are baseline (`61213fe`) and are **now +2 in the working tree**, since T-001 added a `load` line above them. Locate each site by its text rather than jumping to the number.

**Line 146 is not an assertion.** It is control flow inside a `while read` loop:

```bash
while IFS= read -r cask; do
	[[ -n "$cask" ]] || continue
	if ! grep -qxF "cask \"$cask\"" <<<"$rendered"; then
```

Its failure is consumed by `||`, so the errexit bug cannot reach it and it is not masking anything today. Convert it anyway, to:

```bash
	[ -n "$cask" ] || continue
```

Single-bracket, which is measured safe under bash 3.2 errexit and is the idiom `tests/font.bats:552` already uses for this exact construct. The reason to convert a line that is not broken is that leaving it would force the project-wide guard to carry an exemption for `||`-suffixed lines, and an exemption is a hole someone will later walk through with `[[ ... ]] || true`.

**Do not delete line 146.** Removing it satisfies the syntax check while silently stopping the loop from skipping blank lines, and no other check would look at it. That is this task's stated failing example.

**Leave line 105 alone.** It contains `[[` but is a POSIX character class inside a single-bracket test:

```bash
[ "$(grep -c '^[[:space:]]' <<<"$output")" -eq 0 ]
```

Single-bracket assertions propagate correctly under bash 3.2 and are explicitly out of scope for this whole job — there are about 162 of them across the suite and none is being converted.

**Do not** change what any assertion checks, delete or retitle a case, or touch anything under `dot_local/`. Case counts must hold: jsonc 9, licensed-fonts 7, packages 13.

**Verify before reporting done.**
