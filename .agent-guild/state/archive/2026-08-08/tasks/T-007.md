## Spec excerpt

Write `tests/mutation-check.sh`, a committed, reusable script that proves every converted assertion still turns its own test red when its condition is false.

**Why this is the load-bearing deliverable.** A conversion that always passes is the same bug wearing better syntax, and nothing else in this job catches it: the syntax check sees a converted line, the suite sees green. This script is what makes green mean something. It proves each assertion is *wired in* — still evaluated, still able to fail. It does not prove the assertion is meaningful; a human rubric covers that separately, because polarity inversion cannot tell a tautology from a live assertion by construction.

**What it does.** For each of the **53** converted assertions: invert that one assertion, run the file containing it, and require **that specific case** to report `not ok`. Then restore and move on.

**The 53, by file:** apps 11, doctor 20, font 12, jsonc 2, licensed-fonts 5, packages 3.

**Which sites count — read this before you write the enumerator.** "Every helper call under `tests/`" is the obvious implementation and it is wrong. `tests/install-failures.bats` already contains **30** `assert_contains`/`assert_not_contains` call sites, written during the #17 job, and since T-001 moved the helper definitions into `tests/helpers.bash` those calls resolve to exactly the same functions yours do. They are formally indistinguishable from this job's conversions, and a script that globs `tests/*.bats` finds 82-plus sites and fails its own count check on the first run.

Enumerate over **exactly these six files** and no others:

`tests/apps.bats`, `tests/doctor.bats`, `tests/font.bats`, `tests/jsonc.bats`, `tests/licensed-fonts.bats`, `tests/packages.bats`

Two files under `tests/` are excluded by name, and the script should say so where a reader will see it:

- `tests/install-failures.bats` — its 30 call sites predate this job. They are already position-safe and were never part of the 54.
- `tests/lint.bats` — the reintroduction guard. If it uses a helper, counting it would inflate the pinned per-file totals.

Verified before this task was written: those six files contained **zero** helper call sites at baseline, so after conversion every helper call in them is one of yours. That is what makes the per-file counts exact rather than approximate.

**Counting helper calls alone gives 52, not 53, and doctor comes out at 19 rather than 20.** Measured just now on the converted tree:

```text
apps 11   doctor 19   font 12   jsonc 2   licensed-fonts 5   packages 3   = 52
```

The missing one is `doctor.bats`'s disjunction, which T-002 converted to a bare `case` block rather than helper calls, deliberately — a helper-built version would have made this file count 21 and left both of your mutation rules claiming the same lines. So your enumerator must find **two shapes**, not one: helper calls by name, plus that single `case` construct located by its enclosing `@test` name and its `undeclared` / `casks` needles. 52 + 1 = 53, and doctor's 20 = 19 + 1.

If your enumerator reports 52 and stops, it has silently skipped the one site in the job that is not a helper call — which is exactly the "unrecognised site" case that must be a hard error rather than a skip.

**Map each site to the `@test` case that contains it.** You need the case's name to check its TAP line, so the enumerator has to walk backwards from each assertion to its enclosing `@test` and carry that name through. A site whose enclosing case cannot be determined is an unrecognised site: report it and exit non-zero.

**The mutation rule, fixed so you do not have to invent one:**

- A call to `assert_contains` becomes `assert_not_contains` with the same arguments, and vice versa. Polarity inversion, decidable by name.
- The restructured disjunction in `doctor.bats` (baseline line 244, the one testing for `undeclared` or `casks`) is inverted by replacing both needles with a sentinel guaranteed absent from the output. **Locate it by its enclosing `@test` name and its needle strings, not by line number** — this script is advertised as reusable and a line pin goes stale on the next edit.
- Any converted assertion whose form the script does not recognise is **reported by `file:line`, and the script exits non-zero.** Silently skipping an unrecognised site is the one failure mode that lets a dead assertion through, so it is an error, not a warning.

**`packages.bats`'s `[ -n "$cask" ] || continue` is excluded**, and the script should say so. It is a loop guard, not an assertion; inverting it changes which iterations run rather than making a test fail. That exclusion is why the count is 53 and not 54.

**Judge by TAP, never by exit status.** Parse `bats --formatter tap` output and confirm the case you mutated reports `not ok` by name. A file-level non-zero exit is not proof: a mutation that breaks bash parsing collapses the whole file to `not ok 1 setup_file failed` with a warning that 1 of 9 tests ran, the exit code is non-zero, and the case you were probing never executed at all. A script reading exit status scores that a success. This is the single most important property of the script and it is separately checked.

**How you restore is part of the contract.** Copy the original file aside before mutating and copy it back afterwards, including on interrupt or error — a `trap` is the obvious way. **Never restore with `git checkout`.** This is a committed tool that a developer will run against a dirty working tree, where `git checkout` discards their uncommitted work; and during this job, before the commit lands, it would revert every conversion to the baseline the first time it ran.

**Accept an optional file argument.** Given one, mutate only that file's assertions. Three separate checks need a scoped run, and without this each costs a full pass.

**Cost.** Running only the mutated file per mutation is roughly 6 minutes for a full pass, measured against per-file runtimes of about apps 6s, doctor 7s, font 12s, jsonc 0.5s, licensed-fonts 1.4s, packages 2s. Re-running the whole suite per mutation would be about 31 minutes — do not do that.

**Constraints.** No bare `[[` or `((` as a statement; this script is on the guarded surface that `tests/lint.bats` scans, and it runs under the same bash 3.2 with the same bug. It may contain those characters inside quoted patterns, which is what the first-token rule is for. Do not modify any test file's committed content, and leave the tree exactly as you found it.

**Verify before reporting done.**

```bash
git status --porcelain tests/ > /tmp/before
bash tests/mutation-check.sh                       # exits 0, names 53 sites
git status --porcelain tests/ > /tmp/after
diff /tmp/before /tmp/after                        # identical
echo '# marker' >> tests/jsonc.bats && bash tests/mutation-check.sh tests/jsonc.bats
/usr/bin/grep -q '# marker' tests/jsonc.bats       # marker survived the restore
```
