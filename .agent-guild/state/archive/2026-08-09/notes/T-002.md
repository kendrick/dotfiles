# T-002 self-report

## What I built

`tests/sync.bats` — one new file, nothing else touched under `tests/`. It contains:

- A `setup()` that redirects `HOME` and builds `STUBS`, both under `$BATS_TEST_TMPDIR`
  (outside both the scratch git repo and this project repo), sets the stub `PATH`
  authoritatively (`export PATH="$STUBS:/usr/bin:/bin"`, the `apps.bats:73` form, not
  `doctor.bats:62`'s prepending form), pins git author/committer identity so `git commit`
  doesn't fail on a homeless `$HOME`, and writes stubs for `chezmoi` (`source-path`
  no-arg → scratch repo path, `source-path <path>` → exit 1, `re-add` → exit 0, `status`
  → empty), `osascript` (records the full arg list to `$OSA_LOG`), and `date` (fixed
  `2026-01-01`). `code`, `brew`, `jq`, `claude-plugins-capture`, `claude-settings-normalize`
  are never stubbed and aren't reachable via the authoritative PATH — I confirmed this
  by hand (`command -v` for each against `/usr/bin:/bin` only) before relying on it, since
  that's exactly the mechanism the spec calls out as having burned a previous draft.
- `fresh_repo()` — builds a brand-new working repo plus a bare origin per call, seeds one
  commit, `branch -M main`. Called once per `@test`, so every case gets its own repo (no
  reset/clean reuse anywhere).
- Four cases: attached-commits-normally, detached HEAD, rebase in progress
  (`.git/rebase-merge`), merge in progress (`.git/MERGE_HEAD` built via
  `git rev-parse HEAD > .git/MERGE_HEAD`, not an empty file). Each blocked-state case
  asserts its own family string (`Refusing to commit: HEAD is detached` /
  `... rebase in progress` / `... merge in progress`) via `assert_contains`, and asserts
  the other two families' strings are absent via `assert_not_contains`, plus asserts the
  commit count is unchanged from before the run. The attached case asserts exit 0, no
  "Refusing to commit" anywhere in output, `Committed locally` present, and the commit
  count going from 1 to 2.

Every case drives `bash "$SCRIPT"` (the real `dot_local/bin/executable_dotfiles-sync`)
directly — nothing in the file reimplements the guard's branching, and `chezmoi` is never
reachable from the real PATH, so there's no path back to the real
`~/.local/share/chezmoi` even if a stub failed silently (I checked: an unresolvable
`chezmoi` under `set -e` aborts the run rather than falling through to a real binary,
since the restricted PATH has nowhere else to find one).
