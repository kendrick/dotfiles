## Spec excerpt

Add a guard to `dot_local/bin/executable_dotfiles-sync` that refuses to commit when the source dir is in a state from which the commit could never be pushed.

**The defect.** The script commits without ever checking that `HEAD` points at a branch. When it doesn't, the run completes clean and reports success while the commits land where `git push` can't send them and `chezmoi update` can't advance past. This ran undetected on a personal machine from 2026-06-26 to 2026-08-06: an interactive rebase was abandoned mid-flight, leaving the source dir detached, and `dotfiles-sync` then committed onto that detached HEAD 26 times over six weeks. Every run reported success. Meanwhile the machine's source dir stayed frozen 117 commits behind `origin/main`, because a pull can't rebase onto a branch you aren't on. The only symptom that ever reached a human was `chezmoi apply` appearing to do nothing.

The commit phase guards for a clean tree and for a failing commit, but nothing between `cd "$SRC"` at `:128` and `git add -A` at `:140` asks what `HEAD` is.

**Three states to refuse**, and no others:

| state | detected by |
| --- | --- |
| detached HEAD | `git symbolic-ref -q HEAD` exits 1 |
| rebase in progress | `.git/rebase-merge` or `.git/rebase-apply` exists |
| merge in progress | `.git/MERGE_HEAD` exists |

Cherry-pick, revert, and bisect are deliberately out of scope. Bisect detaches HEAD and is already covered by the first row.

**Where the guard goes.** After `cd "$SRC"` at `:128`, and **before** the clean-tree early exit at `:130-133`. A blocked state is refused whether or not there is anything to commit — a detached HEAD with a clean tree still blocks `chezmoi update`, which was half of what the incident cost. This placement is a decision the user settled at Phase 0 and is not yours to revisit.

**Detection order matters.** A rebase in progress is *also* a detached HEAD: `.git/rebase-merge` present and `git symbolic-ref -q HEAD` exiting 1 at the same instant. Check the operation-in-progress markers **first** and report the most specific state that applies, or a stopped rebase gets reported as a bare detached HEAD and the user is handed a recovery command that git will refuse.

**What the refusal must do.**

1. Exit non-zero, create no commit, and never reach `git add -A`.
2. Name which of the three states it found, distinguishably. A reader of `~/.local/state/dotfiles/last-sync.log` should be able to tell a detached HEAD from a suspended rebase from a suspended merge without running another command.
3. Name a command that actually gets the user out of the state it found. The command has to fit the state: what gets you off a detached HEAD is not what finishes a suspended rebase. Do not suggest something merely diagnostic like `git status`, and do not suggest something that silently discards work — on the incident's own repo, `git checkout main` would have stranded 26 commits without saying so.
4. Fire through the existing `notify_fail` helper at `:33-36`, so it reaches the desktop the way every other failure in this script does.
5. Be distinguishable in the log from the existing `==> Nothing to commit. Already in sync.` early exit. Both end the run early; only one is a problem. Do not warn and then fall through to that message.

**What must not change.** On an attached branch with no operation in progress, output and exit code are byte-identical to the script at `298c8a6`, for both the dirty and clean cases. The guard is invisible when it does not fire, so no `==> Source dir is pushable` line.

**Constraints.**

- Touch only `dot_local/bin/executable_dotfiles-sync`. Tests are T-002's; commits are T-003's.
- The change is purely **additive**. Do not delete a line from this script. In particular do not "fix" the pre-existing bare compounds at `:88`, `:122`, `:137`, and do not touch the push path at `:159-182` or its opt-in default — both are documented non-goals.
- bash 3.2 is a hard constraint. The script runs `set -euo pipefail` at `:16`. **No bare `[[` or `((` as a statement in command position** — under bash 3.2 a failing bare compound is discarded unless it is the last statement executed, so `[[ -z "$(git symbolic-ref -q HEAD)" ]]` inside a helper followed by anything else silently reports pushable on a detached HEAD. That is the bug the repo eliminated from its test suite in #21, and reintroducing it here through the fix for a different bug is this task's most likely failure. Use `[ ... ]`, `case`, or a condition position (`if`, `while`).
- A bare command substitution assignment propagates the substitution's exit status under `set -e`. `hits="$(cmd)"` followed by `status=$?` aborts before `status` is read; fold it into `hits="$(cmd)" && status=0 || status=$?`.

**One thing that looks wrong and is not.** A refusal leaves the source dir *dirtier* than it found it, because `chezmoi re-add` at `:66` runs six phases before the guard and has already captured live `$HOME` changes into the working tree. That is deliberate: the capture is safe and useful, only the commit is not. Do not hoist the guard above those phases to "fix" it.

## Running your own code before you report done

You cannot write a test file — that is T-002's — but you must not ship this unrun either. Build a throwaway harness in a scratch directory outside the repo. Nothing here touches a repo file, so it costs you nothing against the scope constraint above, and the checker will build its own anyway.

Six phases run before the guard, and `chezmoi re-add` at `:66` is **not** guarded by `command -v`, so an unstubbed run aborts at that line and never reaches your code. The contract:

- `chezmoi` stubbed: `source-path` with no arguments prints the scratch repo path; `re-add` exits 0; `status` prints nothing; `source-path <path>` exits non-zero so the drift loop at `:87-95` takes its `|| continue` at `:90`.
- `code`, `brew`, `jq`, `claude-plugins-capture`, `claude-settings-normalize` **absent** from `PATH`, so each guarded phase skips. If `$SRC/dot_config/` exists, a present `code` writes into the scratch repo and turns a clean case dirty.
- `osascript` stubbed to a no-op recording its full argument list, so you can confirm the title is `Dotfiles sync failed`.
- `date` stubbed to a fixed value; `HOME` redirected; `DOTFILES_AUTO_PUSH` left unset.
- `export PATH="$STUBS:/usr/bin:/bin"` — **authoritative, not prepended**. `tests/apps.bats:73` is the form. Do not copy `tests/doctor.bats:62`, which appends `$PATH` and lets a tool you need absent resolve to the real binary anyway.
- Stubs and the redirected `$HOME` live **outside** the scratch repo, and each case gets its own freshly built repo with a bare origin. A reset or a clean does not do: neither touches `.git/`, so rebase markers survive into later cases.

Smoke-test all three states plus the attached path, both dirty and clean, and build the merge marker with `git rev-parse HEAD > .git/MERGE_HEAD` — an empty `MERGE_HEAD` makes `test -f` succeed while `git rev-parse --verify -q MERGE_HEAD` fails, so it decides the outcome by construction. Delete each detector **individually** and confirm only its own states stop refusing; the checker runs exactly that, one detector at a time, and a guard where one detector silently covers another's states fails it.
