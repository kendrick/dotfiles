## Spec excerpt

Commit the work from T-001 (the guard in `dot_local/bin/executable_dotfiles-sync`) and T-002 (the harness and cases under `tests/`), and verify the assembled result.

**Commit shape.** Each commit stands alone and is green at checkout. That constrains the order: tests committed before the guard they cover are red at their own checkout, so the guard and its tests go in together, or the guard goes first. Decide which reads better and say why in your report.

**Message standard**, which is the repo's own:

- Explain the **why**, not the what. A message that lists the functions added says what the diff already says. A reader six months on should learn that 26 commits were stranded for six weeks, and that refusing on a clean tree was a deliberate choice rather than an oversight.
- Reference the issue as `Refs #19`. Never `Closes`, `Fixes`, or `Resolves` — the end-to-end verification on a real machine belongs to the user after this job ends, and a closing keyword would auto-close the issue the moment they push.
- No `Co-Authored-By` trailer, and no other co-authorship attribution.
- Do not hard-wrap body lines. Let git's pager and GitHub handle wrapping at display time.
- Voice: a helpful technical writer in a hurry. Commonly recognized abbreviations are fine.

**Scope, which you verify rather than assume.** The whole job touches exactly `dot_local/bin/executable_dotfiles-sync` and paths under `tests/`. Nothing else. Three checks, and the third is the one that catches what the others cannot:

1. `git diff --name-only 298c8a6..HEAD` lists only those paths.
2. Nothing uncommitted remains outside them.
3. `git diff 298c8a6..HEAD -- dot_local/bin/executable_dotfiles-sync | grep -c '^-[^-]'` returns **0**. Both other checks are path-level and neither can see an out-of-scope edit *inside* an allowlisted file, which is where every remaining non-goal in this job lives. Two such edits were measured during this job's constitution audits — flipping the `DOTFILES_AUTO_PUSH` default and "fixing" the pre-existing bare compound at `:137` — and both cleared every path-level check. A guard is an insertion, so a correct implementation returns 0 for free.

The same removed-line count over `tests/` must also be 0. An assertion deleted from inside an existing case is invisible to everything else: the floors count `@test` blocks, the skip check reads added lines only, and a case with one fewer assert still reports `ok`.

**Suite state at the end.** `bats tests/` exits 0 with nothing skipped or deleted. Per-file floors hold at or above apps 18, doctor 11, font 44, install-failures 17, jsonc 9, licensed-fonts 7, lint 1, packages 13. The total rises above 120, because this job adds cases and removes none.

**Do not push.** Committing is the whole of this task. The user pushes by hand, always, and that is a standing rule in this repo rather than a preference for this job.
