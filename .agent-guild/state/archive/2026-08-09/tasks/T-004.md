## Spec excerpt

Add at least one committed bats case covering a **clean-tree** refusal to `tests/sync.bats`, and nothing else.

**Why this exists.** All four cases that file currently ships write `change.txt` into the scratch repo before invoking the script, so every one of them exercises the dirty path. Refusing on a clean tree is a deliberate decision the user made at Phase 0: a detached HEAD with nothing to commit still blocks `chezmoi update`, and that was half of what the six-week incident cost. The guard therefore sits after `cd "$SRC"` at `:128` and **before** the clean-tree early exit at `:130-133`.

Right now nothing permanent proves that placement. If a later edit moved the guard below `:130-133`, the clean path would silently stop being guarded, a detached machine would go back to failing `chezmoi update` in silence, and the entire suite would stay green. T-001's three per-detector deletions do not catch it either, because the detectors would all still be present — just unreachable on the clean path.

**What to add.** At minimum one case: a blocked state, a clean working tree, asserting the run refuses and names its state. Detached HEAD is the obvious choice, since it is the incident's own state. More than one is fine if you think the rebase and merge states earn their own clean cases; say why in your report if you add them.

**How the case has to be built.**

- Reuse the harness already in `tests/sync.bats`. Do not write a second one, and do not modify the existing one unless a clean case genuinely cannot run under it — if that happens, report it rather than quietly reshaping the harness the checker already verified.
- The case gets its **own freshly built scratch repo**, like every other. Not a reset, not a clean, and not another case's repo.
- Write **nothing** into the scratch repo before invoking the script. That is the whole point of the case, and it is the easiest thing to get wrong: the harness's own setup must leave the porcelain empty. Assert that it is empty before the run, so a future change that dirties the fixture fails loudly here rather than turning this case into a fifth dirty one.
- Assert the refusal names its state, and assert the other states' messages are absent, matching how the four existing cases assert.
- Assert **no commit was created** and that the log does **not** contain `Nothing to commit. Already in sync.` — that second assertion is what distinguishes this case from a guard that fell through to the clean-tree branch.

**Verify it discriminates before you report done.** Take a copy of `dot_local/bin/executable_dotfiles-sync` to an absolute path outside the repo. Move the guard block to *below* the clean-tree exit at `:130-133`, run the suite, and confirm your new case reports `not ok` while the four dirty cases stay green. Restore from your copy and `diff` to verify. This is a relocation, not a deletion — a case that only goes red when the guard is deleted entirely is not testing placement.

**Constraints.**

- Ship only `tests/sync.bats`. Do not modify `dot_local/bin/executable_dotfiles-sync` except through the relocation above, which must leave it byte-identical, digest `c90191bfb7fa6d48dc7deb5d6bb51fe41cebfa84446816ab206a2410fc04dc73`.
- Never `git checkout` that file. The guard is uncommitted until T-003 and a checkout would revert all of it, unrecoverably.
- Do not commit anything. `HEAD` must still be `298c8a6` when you finish.
- Do not modify any pre-existing test file other than `tests/sync.bats`, and do not delete or edit a line of the four cases already in it. Add.
- bash 3.2, and `tests/lint.bats` scans this file: no bare `[[` or `((` as a statement in command position.
