## What I built

`run_onchange_install-packages.sh.tmpl`: factored the existing two awk-based log
parsers into `parse_failed_entries`/`parse_fetch_batch`, and added
`handle_bundle_result(log, status, allow_retry)`, which reports a completed `brew
bundle` attempt and, only when `allow_retry=1` and at least one (but not all)
batched names resolve via `brew info`, drops the unresolvable lines from the
Brewfile and retries once — recursing into itself with `allow_retry=0` so the
retry's own outcome is reported through the same logic but can never trigger a
third `brew bundle` call. The retry gate is a count comparison
(`${#missing_arr[@]} -lt ${#fetch_arr[@]}`), not "Brewfile non-empty," per the
task's explicit warning that the fetch batch is a handful of entries out of dozens
in the full file. Array expansions are count-guarded per the bash 3.2 note.

`tests/install-failures.bats`: added a `render_brewfile()` helper that renders just
the `Brewfile` template partial under the real `$HOME` (mirroring `render_script`'s
reasoning), used to read real entry names for the new cases rather than inventing
fixtures. Added the four required cases:

- `drop-and-retry, mixed batch installs the survivors` — 3 real names, 1 fails
  `brew info`; the stub logs one line per `bundle` call to a per-case
  `$BATS_TEST_TMPDIR/bundle-calls.log` and saves each call's received Brewfile
  under `$BATS_TEST_TMPDIR/bundle-brewfiles/<n>`; asserts the log holds 2 entries
  and the second Brewfile has both survivors and not the dropped name.
- `drop-and-retry, all unresolvable reports without retrying` — 2 real names, both
  fail `brew info`; asserts the log holds exactly 1 `bundle` entry.
- `no extra brew calls on a clean run` — `bundle` exits 0 on the first call; asserts
  `info` count 0 and `bundle` count 1.
- `reports and stops after a second failure` — first `bundle` dies in the fetch
  phase (1 of 2 names unresolvable), second dies in the install phase; asserts
  `bundle` count is exactly 2.

Each case runs `run bash "$script"` exactly once and logs to a file under
`$BATS_TEST_TMPDIR` (bats gives each `@test` its own), never
`BATS_SUITE_TMPDIR`.
