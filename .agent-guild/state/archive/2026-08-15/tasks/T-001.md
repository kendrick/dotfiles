## Spec excerpt

### The bug

One Brewfile entry that brew cannot resolve stops every other package from installing. Homebrew batch-fetches everything that needs downloading before it installs anything, and its bundle command's `installer.rb:81-88` returns on a fetch failure — above the install phase. So a single unresolvable name means zero packages install. Not "the bad one is skipped": zero.

This is not hypothetical. `deskflow` was removed from homebrew-cask, sat in `.chezmoidata.toml`, and aborted every package install on a personal machine for an unknown stretch, stranding `sbcinnovation/tap/squoosh`, `databricks/tap/databricks`, `font-fantasque-sans-mono-nerd-font`, `zappy`, and three App Store apps behind it.

Observed today:

```text
Fetching definitely-not-a-real-formula-xyz, sbcinnovation/tap/squoosh, databricks/tap/databricks, font-fantasque-sans-mono-nerd-font, deskflow, zappy
`brew bundle` failed! Failed to fetch definitely-not-a-real-formula-xyz, sbcinnovation/tap/squoosh, ...
Homebrew ran, but these Brewfile entries don't exist (its errors are above):
  definitely-not-a-real-formula-xyz
  deskflow
```

Both dead names are correctly identified. Six entries were in the batch; four were fine and none of those four installed.

### What to build

`run_onchange_install-packages.sh.tmpl:62-105` already handles the fetch phase and already re-derives which batched name is unresolvable, via `brew info`. Build on that rather than validating up front — pre-checking all 88 entries would mean 88 `brew info` calls on every apply to guard a case that almost never fires.

On a fetch failure the installer already knows which names fail to resolve. Drop those lines from the rendered Brewfile, run `brew bundle` once more with what is left, and report the dropped entries by name. The cost lands only on the failure path; the happy path is untouched.

A second run that fails again for a different reason reports and stops rather than looping.

**What gates the retry.** Skip the retry when *every name in the failed fetch batch* was unresolvable — not when the Brewfile would be left empty. Those are different conditions and they produce different implementations. `fetch_batch` holds only the entries brew needed to download, which on a real machine is a handful out of 88, so "drop the dead ones and the Brewfile still has entries in it" is true even when every batched name was dead, and a retry gated that way runs a second `brew bundle` that case 2 below forbids.

Exit 0 throughout. #17 settled that aborting the apply is a non-goal: stopping here would strand every later script over one unavailable formula.

### Required test coverage

All of it drives the script as a real subprocess with `brew` stubbed on PATH, per the conventions already in `tests/install-failures.bats`. Nothing here may reach real Homebrew or install anything.

Four cases, and the exact description substrings matter because the checks filter on them with `bats -f`:

1. **`drop-and-retry`, mixed batch.** Three names, one failing `brew info`. Assert a recorded log of every `brew bundle` invocation holds two entries, and that the second invocation's Brewfile carries both survivors and not the dropped name.
2. **`drop-and-retry`, all unresolvable.** Every name fails `brew info`. Assert the log holds exactly one `bundle` invocation — the script reports them all rather than retrying against an empty Brewfile.
3. **`no extra brew calls`.** A run where `brew bundle` exits 0. Assert the `info` count is 0 and the `bundle` count is 1, which is what the script does today.
4. **`reports and stops`.** First `bundle` dies in the fetch phase with one unresolvable name; the second dies in the install phase. Assert the `bundle` count is exactly 2.

Exactly two cases may carry `drop-and-retry` in their description — C-1's check asserts that count and goes red at one or three.

### Traps that have already cost this job time

**Proof by summary text is not proof.** `run_onchange_install-packages.sh.tmpl:94-95` already prints the unresolvable name with a two-space indent. A case asserting `[ "$status" -eq 0 ]` plus `assert_contains "  fixture-nonexistent-xyz"` passes against the installer as it stands today, with no retry branch at all. The audit built exactly that pair and watched it go green. Assertions must read a recorded log of `brew bundle` invocations and the Brewfile each one received.

**Invented names make the assertion vacuous.** Read the three names for case 1 out of the rendered Brewfile. Against a fixture name the render never contained, dropping it is a no-op, the second Brewfile equals the first, and "not the dropped name" is true for the wrong reason.

**One `run bash "$script"` per case.** Driving the installer twice inflates the invocation log until a count assertion passes on an installer that never retried. The log must be per-case, not shared across cases via `BATS_SUITE_TMPDIR`.

**bash 3.2.** `/bin/bash` on this machine is 3.2 and renders an empty array as one empty word under `set -u`. Guard every array expansion with `[ "${#arr[@]}" -gt 0 ]`. Note `[ ]`, not `[[ ]]` — a `[[ ]]` count assertion gates nothing under this bash, and `tests/lint.bats` catches it by file and line.

**Do not touch `.chezmoidata.toml`.** Whether a vanished package was renamed, moved to a tap, or genuinely dropped is a human call. Report it; do not edit the registry.

**Do not touch `_working-memory/`.** T-003 owns it and updates it once the job lands. T-002 is running concurrently with you, so a write there from either of you would clobber the other's with nothing in the wave able to detect it.

### Read first

- `run_onchange_install-packages.sh.tmpl:62-105` — the fetch-phase handling this builds on, including the `brew info` re-derivation.
- `tests/install-failures.bats:107-162` — the two existing fetch-phase cases and the stub conventions. The comment at `:130-131` names the summary-text trap above.
- Homebrew's own `installer.rb:81-114`, under its bundle command — the two failure phases and the five distinct failure strings they emit. Assuming one shape is what caused this bug's predecessor.

### Out of scope

Removing dead entries from the registry automatically. Making `run_onchange` retry until it succeeds. Aborting the apply on failure. Progress display (#16 owns that). Pre-validating entries before the fetch.
