## Diagnosis

- **C-1** (blocker): the check does not discriminate against the artifact the clause exists to forbid.

  `.agent-guild/scripts/check-build.sh 'bats -f "drop-and-retry" tests/install-failures.bats'` proves one thing: some test whose description contains `drop-and-retry` passes. It cannot see how many such tests there are, and it cannot see what they assert. Both halves of C-1's own text turn on exactly those two facts.

  Demonstrated, not reasoned. `apparatus/CON-audit-r0/gapc/` holds two `drop-and-retry` cases that no one would flag on review — they stub `brew`, drive the script as a subprocess, and assert `[ "$status" -eq 0 ]` plus `assert_contains "  fixture-nonexistent-xyz"` against the script's own two-space-indented summary, which is precisely the discipline C-5 asks for. Run against `REF_VARIANT=baseline`, the installer as it stands in the tree today with no retry at all, the filter exits 0. C-1's stated failing example — "the installer prints the unresolvable name and exits, leaving the stub's bundle-invocation log with exactly one entry and every survivor uninstalled" — passes C-1's check. The reason is structural: today's script already prints the indented name (`run_onchange_install-packages.sh.tmpl:94-95`), so every assertion that doesn't count `brew bundle` invocations is satisfied by the bug.

  The count half is separately broken. `apparatus/CON-audit-r0/gap/` carries only the first of the two cases and runs against `REF_VARIANT=empty-retry`, an implementation that bundles a second time even when nothing survived — the behavior C-1's text names outright ("rather than retrying against an empty Brewfile"). Filter exits 0. The all-unresolvable path ships unchecked whenever the worker writes one case instead of two.

  What would close it, in the clause's own idiom:
  - Add the count to the check. `bats -c -f "drop-and-retry" tests/install-failures.bats` prints `2` against the reference and `1` against the one-case suite, verified in this round, so the check can read `.agent-guild/scripts/check-build.sh '[ "$(bats -c -f "drop-and-retry" tests/install-failures.bats)" -eq 2 ] && bats -f "drop-and-retry" tests/install-failures.bats'`.
  - Name the invocation-counting assertion as a requirement of the clause rather than as narrative, and give it a checker that reads it (see C-5 below). The distinguishing observation is the `brew bundle` call count and the second call's stdin — nothing else separates a fixed script from the reported bug.

- **C-5** (blocker): the constitution has no check for whether a new case asserts what its clause describes, and C-5 is the only place that hole can be closed.

  C-5's rubric fails a case that invokes real brew, mutates machine state, or proves its claim by matching stub-echoed text. All three are real traps and the clause catches them. None of them is the trap that matters here. The `gapc` cases pass C-5 as written — they assert against the script's own indented summary, exactly as the rubric requires — and they also pass against a script with no drop-and-retry branch in it. C-1, C-2 and C-3 each spell out the assertion their case must carry (the second invocation's Brewfile; `info` count 0 and `bundle` count 1; `bundle` count exactly 2), and those sentences are load-bearing text that routes to checker-deterministic, which only runs scripts and reads nothing.

  What would close it: extend C-5's FAIL conditions to include a case that does not carry the assertion its clause names — the second `brew bundle` invocation's Brewfile contents for C-1's first case, the absence of a second invocation for C-1's second, the `info`/`bundle` counts for C-2, the count of exactly 2 for C-3. That keeps the deterministic filters where they are and puts the one judgment a script can't make in front of the checker who is already reading these files.
