**Are T-003's unclause-checked deliverables a real gap?** Split the question; the two halves don't answer the same way.

Its real consumers are the return gate and your invalidation decision, and for the latter the checker's verdict carries the same failing output independently. The **working-memory prose** is a real gap, and it is where the finding above lives. Unlike the report it ships, it is the one deliverable in the job with no clause of any kind touching its content, and its instruction is currently wrong. Note that this is not a spec-coverage failure — you're right that #22 says nothing about working memory — which is exactly why it needs saying out loud: it is scope the constitution admitted through C-7's allowlist without admitting the obligation that comes with it. The cheap fix is the wording; the thorough fix is a clause. Either is defensible, but shipping the current sentence is not.

**Is worker-standard/sonnet the right rung?** Yes, and I'd resist moving it. Working memory is machine-first scaffolding — your own precedent says so in as many words, `archive/2026-08-08/tasks/T-008.md:14`: "Working memory is machine-first: judge on factual accuracy against the constitution's Measured baseline, not on tone." Prose judged on factual accuracy against a recorded baseline is correctness work, which is the worker-standard row. It is also the category the user's own prose rule explicitly exempts, as an internal intermediate rather than something read for its own sake. Moving to worker-craft would be routing on the fact that the output is words, which the table warns against in both directions.

What actually distinguishes T-008's opus routing is not the writing — it is that T-008 had a judgment clause and a rubric to satisfy. The tier followed the check, not the prose. So if you add a clause here, revisit the rung then; on the task as written, sonnet is right and haiku would have been too low.
