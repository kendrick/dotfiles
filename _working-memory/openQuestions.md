- Arrow ligatures (`->`, `=>`) don't render in Ghostty or the VS Code integrated terminal, while the equals family (`==`, `!=`, `===`) does, and everything renders correctly in the VS Code editor. No mechanism found. Ruled out with evidence, so don't re-derive: it isn't font-specific (Fantasque and MonoLisa fail identically), isn't the Symbols fallback stacking (Fantasque's block has no fallback line), isn't the feature string (`calt` alone and `dlig,liga` fail the same way), and isn't missing glyphs — Fantasque carries `hyphen_greater.liga` and `equal_equal.liga` side by side, both reachable only through `calt`, the one substitution feature it exposes. Adding `liga` and `ss01` to the Ghostty block changed nothing. Ghostty is 1.3.1, past the 1.2.0 release that turned ligatures off by default. Next lead if it ever matters: some fonts gate arrows behind a named stylistic set (Monaspace uses `ss03` for `->`, `ss02` for `<=`), so a per-font terminal feature string naming the arrow set may fix it for the fonts that have one. Cosmetic, terminal-only, and accepted as-is for now. _(2026-08-05)_
